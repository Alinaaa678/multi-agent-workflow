# GitHub 协作与分支流程

## 日常开发

从最新 `integration` 创建任务分支，在任务分支完成实现和测试，再向对应工作块分支或 `integration` 创建 Pull Request。PR 描述应写明任务编号、需求引用、修改范围、测试命令、测试结果和已知限制。

## 合并顺序

1. 工作块分支完成独立测试。
2. PR 通过代码审查和 CI 后合并到 `integration`。
3. 在 `integration` 运行跨模块联调与回归。
4. B01 检查需求追溯，B06 检查证据和验收结果。
5. 集成版本稳定后再合并到 `main`。

## 冲突处理

先以冻结的接口契约和版本记录判断冲突，再修改代码。共享接口变更必须同步所有消费方，并在集成分支重新运行受影响测试。
